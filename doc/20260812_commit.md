# 변경사항 정리 (Monaco 스크립트 에디터 + 그룹 색상)

커밋 전 정리용 문서. 아래 세 덩어리로 진행됐습니다.

1. Monaco 에디터 도입 (어제)
2. 스크립트 에디터 버그 수정 + 도움말 기능 (오늘)
3. 삽입 그룹별 색상 구분 (오늘)

## 1. Monaco 에디터 도입

`ScriptNode`의 `Script` 속성(meta의 `customEditorTypeName: "ScriptEditor"`)을 편집할 때
일반 `<input>` 대신 Monaco 에디터를 모달로 띄우도록 함.

**추가된 파일**
- `src/components/ScriptEditorModal.jsx` — Monaco를 감싸는 모달. 배경 클릭/Escape로 닫힘.
- `src/lib/monacoSetup.js` — Monaco를 CDN이 아니라 로컬 번들(`monaco-editor` 패키지)로 셀프호스팅하도록 설정. 사내망처럼 외부 네트워크가 막힌 환경에서도 동작하게 하기 위함.
- `scripts/gen-util-dts.cjs` — `sample-meta.json`의 `ScriptNode.description`에 텍스트로만 존재하던 `util.*` 71개 함수 목록을 파싱해서 TypeScript 선언(.d.ts)으로 변환하는 스크립트. `npm run gen:util-types`로 재실행 가능.
- `src/lib/scriptUtilTypes.generated.js` — 위 스크립트의 생성 결과물 (문자열로 export). **손으로 수정하지 말 것.**

**수정된 파일**
- `src/components/PropertyPanel.jsx` — `customEditorTypeName === 'ScriptEditor'`인 속성은 `ScriptEditorField`로 렌더링하도록 분기 추가.
- `vite.config.js` — `worker: { format: 'es' }` 추가 (Monaco 자체 워커가 ES 모듈이라 필요).
- `package.json` — `@monaco-editor/react`, `monaco-editor` 의존성 및 `gen:util-types` 스크립트 추가.

**특이점**
- 설치된 `monaco-editor`가 0.56.0으로, 흔히 예제에서 보이는 `monaco.languages.typescript.javascriptDefaults` 네임스페이스가 없다. 대신 `monaco-editor/language/typescript/monaco.contribution`이 `javascriptDefaults`를 flat named export로 제공 — 이걸 직접 import해서 씀.
- 같은 이유로 워커 import 경로도 다르다. `monaco-editor`의 `package.json` `exports` 맵이 이미 `esm/vs/`를 붙여주기 때문에, `monaco-editor/esm/vs/editor/editor.worker`처럼 쓰면 경로가 중복돼서 깨진다. 맞는 경로는 `monaco-editor/editor/editor.worker` (접두사 없이).
- `util.*` 자동완성은 순수 IntelliSense용 타입 선언일 뿐, 실제 실행 환경(C# 시나리오 매니저)을 흉내내지 않는다. 브라우저에서 `util.print()` 같은 걸 실제로 실행하지 않음.

## 2. 스크립트 에디터 버그 수정 + 도움말 기능

**버그: 모달 안에서 클릭하면 포커스가 "스크립트 편집..." 버튼으로 튐**

원인은 `PropertyPanel.jsx`의 `Field` 컴포넌트가 children을 `<label>`로 감싸는 구조였는데,
`ScriptEditorModal`을 그 `<label>` **안쪽에** 렌더링하고 있었던 것. 브라우저는 `<label>` 내부
클릭 시 (화면상 실제 위치와 무관하게, DOM 구조만 보고) 연결된 폼 컨트롤에 자동으로 포커스를
넘기는 네이티브 동작이 있어서, 모달이 `position: fixed`로 전체 화면을 덮고 있어도 그 안의
모든 클릭이 뒤에 있는 버튼으로 흡수됐다.

- **수정**: `ScriptEditorField`에서 모달을 `<Field>`(label) 밖으로, 형제 엘리먼트로 뺌.
- 부수적으로 Monaco 옵션에 `editContext: false` 추가 — Chrome의 최신 EditContext API 입력
  경로 대신 기존에 잘 검증된 textarea 기반 입력 방식을 쓰도록 함 (이번 버그의 직접 원인은
  아니었지만 더 안정적).

**도움말 버튼 추가**

`ScriptNode`의 node-level `description`(문법 설명 + util.\* 71개 함수 레퍼런스)이 전에는
프로퍼티 패널 하단에 통째로 표시되고 있었는데, 이걸 스크립트 모달 안의 "도움말" 토글 버튼으로
옮김.

- 모달 헤더에 "도움말" 버튼 → 클릭 시 에디터 오른쪽에 360px 도움말 패널이 열림/닫힘.
- Escape 키는 도움말이 열려 있으면 도움말만 먼저 닫고, 닫혀 있으면 모달을 닫음 (편집 중이던
  내용을 실수로 날리지 않도록).
- 원본 description 텍스트는 XML 소스의 탭/줄바꿈이 그대로 붙어있어서 한 줄로 뭉쳐 보였는데,
  줄 단위로 trim 후 재조합하는 `formatHelpText()`로 정리해서 번호 목록이 읽기 좋게 나오도록 함.
- 프로퍼티 패널 쪽에서는 `ScriptEditor` 타입 속성이 있는 노드에 한해 하단 설명 블록을 더 이상
  표시하지 않음 (`hasScriptEditorProp()` 체크).

**수정된 파일**
- `src/components/ScriptEditorModal.jsx` — 도움말 토글/패널, `editContext: false`.
- `src/components/PropertyPanel.jsx` — 모달을 label 밖으로 이동, `nodeDescription`을
  `helpText`로 전달, 하단 설명 블록 조건부 숨김.
- `public/css/script-editor-modal.css` — 도움말 버튼/패널 스타일.

## 3. 삽입 그룹별 색상 구분

삽입 탭의 시나리오/음성/컨트롤/서비스 그룹마다 색을 다르게 줘서 리본 메뉴와 실제 캔버스
블록 아이콘 배경이 서로 대응되도록 함.

- 시나리오: 파랑, 음성: 청록, 컨트롤: 주황, 서비스: 보라 (`groupColors.js`에서 한 곳에 정의).
- 블록 몸통은 그룹색의 옅은 톤, 아이콘 영역은 그룹색 원색 — 기존 기본 배색(연회색 몸통 + 진회색
  아이콘)의 명암 구조를 그대로 유지하면서 색만 그룹별로 바꾼 것.

**추가된 파일**
- `src/lib/groupColors.js` — 그룹→색 매핑과 팔레트 헬퍼 (`colorForGroup`,
  `groupColorStyle`, `buildGroupColorPallete`, `paletteKeyForGroup`).

**수정된 파일**
- `src/components/RibbonMenu.jsx` — 삽입 탭의 각 `RibbonGroup`에 CSS 커스텀 프로퍼티
  (`--group-color`, `--group-color-bg`)를 인라인으로 전달.
- `public/css/ribbon-menu.css` — 그룹 상단 컬러 바, 그룹 라벨 텍스트, 아이콘 placeholder
  배경에 위 변수 적용 (변수가 없는 다른 탭은 기존 모습 그대로 — fallback 값 사용).
- `src/components/DiagramCanvas.jsx` — 새 블록이 생성되는 시점에 그룹 색을 적용.

**특이점**
- `diagram-library.js`는 **한 줄도 수정하지 않음** (프로젝트 기존 원칙 유지). 색상 적용은
  라이브러리가 이미 제공하는 `block.setColor(bgColorKey, iconColorKey)` API를 그대로 쓰고,
  커스텀 색은 `diagram.options.colorPallete`에 이름으로 등록해서 그 이름으로 조회하는 방식.
  `colorPallete`는 라이브러리 내부에서 `mergeDeep`으로 병합되기 때문에, 우리가 넘긴 값이
  라이브러리의 기본 팔레트(red/blue/green 등 18개)를 지우지 않고 추가되기만 함.
- `onNodeCreated` 이벤트는 `diagram.ready === true`일 때만 발생하는데, 이 스캐폴드는
  `deserialize()`(파일 열기)를 호출한 적이 없는 새 캔버스라 `ready`가 영원히 `false` —
  즉 리본에서 새로 놓은 블록에 대해 `onNodeCreated`가 **절대 발생하지 않는다** (이건 이번에
  발견한 게 아니라 `DiagramCanvas.jsx`에 이미 주석으로 남아있던 known issue). 그래서 색을
  입힐 새 블록을 콜백으로 받는 대신, `diagram.nextSeq - 1`로 만들어진 id를
  `diagram.components`에서 직접 찾아오는 방식을 씀 — `Component` 생성자가 동기적으로
  `diagram.components.set(id, this)`를 하기 때문에 클릭 이벤트 핸들러 안에서 바로 조회 가능.
- `[MEMO]`(빈 블록)는 `meta.nodes`에 없어서 group이 없고, `Memo`는 `setColor`가 없어서
  색 적용 로직이 자연히 스킵됨 (별도 예외처리 안 함).
