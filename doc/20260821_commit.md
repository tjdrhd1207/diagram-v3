# 변경사항 정리 (프로젝트 파일 관리 + 레거시 XML 임포터 + 리본 UI 개선)

커밋 전 정리용 문서. 아래 네 덩어리로 진행됐습니다.

1. PropertyPanel 필드별 인라인 설명
2. 프로젝트 파일 관리 (새 프로젝트 / 열기 / 저장 / .prj 프로젝트 열기)
3. 레거시 ScenarioDesigner .xml 페이지 임포터 + `designer.meta.json` 전환
4. 리본 "삽입" 탭 — 카테고리 플라이아웃으로 재설계

---

## 1. PropertyPanel 필드별 인라인 설명

기존엔 필드 설명이 패널 하단 한 곳에 모여 있어서, 보려면 스크롤해야 했음. 필드를
클릭하면 그 필드 바로 아래에 설명이 뜨도록 변경(3안 중 사용자가 선택한 "B. 필드
바로 아래 인라인" 방식).

- `FieldDescriptionContext`가 들고 있던 값을 "설명 문자열"에서 `{ activeFieldKey,
  setActiveFieldKey }`로 변경. 각 `Field` 호출부가 자기 `fieldKey`를 갖고 있다가,
  포커스 시 그 key를 컨텍스트에 올리고, 자기 key가 활성 key와 같을 때만 스스로 설명을
  그린다.
- 노드 레벨 설명(`nodeDescription`, 패널 맨 아래)은 필드 포커스와 완전히 분리 —
  어떤 필드에 포커스가 있든 없든 항상 표시.

**수정된 파일**
- `src/components/PropertyPanel.jsx` — `Field`가 `fieldKey` prop을 받아 컨텍스트의
  `activeFieldKey`와 비교, 자기 설명을 `children` 아래에 인라인으로 렌더링. 모든
  `Field`/`ScriptEditorField` 호출부에 `fieldKey` 배선.
- `public/css/property-panel.css` — `.property-field-description` /
  `.property-field-description-icon` 추가 (기존 하단 전용 `.property-panel-description`과
  시각적으로 비슷하지만 훨씬 작고 필드 바로 아래에만 나타남).

## 2. 프로젝트 파일 관리 (새 프로젝트 / 열기 / 저장 / .prj 프로젝트 열기)

as-is 도구처럼 파일을 불러오고 저장하는 기능이 전혀 없던 상태에서, 리본 "파일" 탭에
전체 파일 관리 기능을 새로 만듦.

**단일 파일 열기/저장**
- "새 프로젝트": 확인창 후 캔버스를 완전히 새로 시작. `DiagramCanvas`가 마운트 시점에
  딱 한 번 `Diagram` 인스턴스를 만드는 구조라, `canvasKey`를 올려서 컴포넌트 자체를
  리마운트시키는 방식으로 구현 (새 `useId` → 새 svgId → 새 `Diagram`).
- "열기": `.xml` 파일 하나를 골라 `FileReader`로 읽고 `initialXml`에 담아 캔버스를
  리마운트. `DiagramCanvas`는 `initialXml`이 있으면 `new Diagram()` 대신
  `Diagram.deserialize()`로 시작하도록 분기.
- "저장": `Diagram.serialize()` 결과를 `scenario.xml`로 다운로드.
- `DiagramCanvas`에 `findMissingMetaNames()` 사전 검사 추가 — `Block.deserialize()`가
  `meta.nodes[metaName]`을 가드 없이 읽어서 없는 타입이면 그 자리에서 크래시하는데,
  실제로 호출하기 전에 미리 훑어서 어떤 타입이 빠졌는지 알림으로 알려주고 빈 캔버스로
  안전하게 폴백하도록 함.
- 모든 `FileReader` 사용처에 `onerror` 핸들러 추가 — 이게 없으면 읽기 실패가 완전히
  조용해서(`onload`가 그냥 안 불림) "클릭했는데 아무 일도 안 일어남"으로만 보였음.

**`.prj` 프로젝트 열기 (폴더 선택)**
- `.prj`는 시나리오가 아니라 **프로젝트 인덱스**임을 실제 샘플로 확인 — 프로젝트
  전역 변수/공용 스크립트/빌드 설정 + `<ItemGroup><Page Include="파일명.xml"
  Tag="메뉴이름">` 나열만 갖고 있고, 실제 시나리오는 같은 폴더의 개별 `.xml`
  파일들에 있음.
- `webkitdirectory` 폴더 선택으로 `.prj`와 그 옆의 `.xml`들을 한 번에 읽어들여서,
  `ProjectPagesPanel`(검색 가능한 평평한 페이지 목록, 캔버스 왼쪽)에 표시. `IsStart`
  페이지를 자동으로 캔버스에 로드.
- 폴더에 실제로 없는 페이지는 "파일 없음" 배지 표시. 처음엔 `disabled` 버튼으로
  막았었는데, disabled면 `onClick` 자체가 안 떠서 "클릭해도 반응 없음"으로 보이는
  문제가 있어 — 클릭은 항상 되게 하고 없으면 alert로 명확히 알려주는 방식으로 수정.

**추가된 파일**
- `src/lib/prjFile.js` — `.prj` XML 파서 (`parsePrjXml`, `findPrjFile`,
  `buildFileIndex`).
- `src/components/ProjectPagesPanel.jsx` — 페이지 목록 사이드 패널 (검색 + 평평한
  목록, 파일명 접두사로 계층이 느껴지지만 `.prj`에 명시적 부모-자식 필드가 없어서
  트리로 재구성하지 않음).
- `public/css/project-pages-panel.css`

**수정된 파일**
- `src/App.jsx` — `canvasKey`/`initialXml`/`project`/`activePageInclude` 상태,
  파일/폴더 입력 두 개(숨김), 관련 핸들러 전부.
- `src/components/DiagramCanvas.jsx` — `initialXml` prop, `Diagram.deserialize()`
  분기, `findMissingMetaNames()`, `onLoadError` prop, `serialize()` 메서드
  (`useImperativeHandle`).
- `src/components/RibbonMenu.jsx` — "파일" 탭에 새 프로젝트/열기/프로젝트 열기/저장
  버튼 추가.

**특이점**
- **진짜 버그 하나 발견**: `e.target.files`는 input에 물려있는 "라이브" `FileList`라,
  읽은 직후 `e.target.value = ''`로 리셋하면 이미 들고 있던 참조까지 같이 비어버림
  (같은 객체를 나중에 다시 읽어도 length가 0). 폴더 선택 핸들러에서 이걸로 파일이
  통째로 사라지는 문제가 있었음 — `[...e.target.files]`로 즉시 배열 복사해서 해결.
  단일 파일 열기 쪽은 `File` 객체를 바로 인덱싱해서 뽑아뒀기 때문에 원래 문제 없었음
  (`File` 자체는 라이브가 아니라 `FileList` 컨테이너만 라이브).
- `diagram-library.js`는 이번에도 전혀 건드리지 않음.

## 3. 레거시 ScenarioDesigner .xml 페이지 임포터 + `designer.meta.json` 전환

`.prj`가 가리키는 실제 페이지 파일(`123.xml`)을 열어보니 화면에 아무것도 안 나타나서
조사한 결과, 실제 파일이 `Diagram.serialize()`/`deserialize()`가 다루는
`<scenario><block>` 포맷이 아니라 **디자이너 자체 편집 포맷**
(`<Diagram><Nodes><Node NodeType="...">`, .NET 직렬화기가 그대로 찍어낸 형태)임을
확인. 실제 샘플(`123.prj`, `123.dxml`, `123.xml`)을 직접 대조해서 변환 규칙을 확정.

또한 작업 도중 기존 `sample-meta.json`(13종 노드)이 `designer.meta.json`(66종 노드,
사용자가 새로 제공)으로 교체되면서 `App.jsx`의 import가 깨져 있던 것도 같이 고침.

**매핑 규칙 (실제 파일 대조로 확정)**
- `NodeType` 속성이 그대로 우리의 meta-name (역매칭 불필요).
- `<Bounds>x, y, w, h</Bounds>`가 그대로 `<svg><bounds>x,y,w,h</bounds></svg>` —
  **좌표가 원본에 있어서 자동배치가 필요 없음** (`.dxml`은 빌드 산출물이라 좌표가
  아예 없어서 자동배치가 필요했을 것 — 그래서 `.dxml`이 아니라 `.xml` 기준으로
  가기로 결정).
- 링크의 `Origin`/`Destination`은 `<Node>`의 파일 내부 임시 `Id`(0,1,2,...)를
  참조하므로, 전체 `<Nodes>`를 먼저 스캔해 `내부Id → Sequence`(우리 block id) 맵을
  만들고 치환.
- `<Links>`가 노드 타입과 무관하게 실제 존재하는 모든 분기를 그대로 나열함을
  확인(`SwitchNode` 같은 "동적 분기" 타입도 예외 아님 — 실제 `.dxml`의 `<switch>`
  블록이 다른 노드와 동일한 평범한 `<choice>` 구조였음) — 그래서 노드 타입별 특수
  처리 없이 모든 타입을 동일한 알고리즘으로 처리 가능.
- 프로퍼티는 `designer.meta.json`의 `sourceName`(디자이너 필드명) → `buildName`
  (우리 시스템이 쓰는 이름) 매핑을 그대로 기계적으로 적용. `buildDataType`이 있으면:
  - `'CData'` → 속성이 아니라 자식 엘리먼트 + 텍스트로 (예: ScriptNode의 Script →
    `<javascript><source>...</source></javascript>`).
  - `'XmlChild'` → 원본 서브트리를 그대로 복제해서 태그 이름만 buildName으로 교체.
  - `buildName`이 빈 문자열이면 저장 대상이 아니므로 건너뜀 (예: SwitchNode의
    `SwitchCase` — 실제 분기는 `<Links>`에서 이미 나옴).
- `buildScript` 필드(빌드 산출물 생성 전용 변환식)는 이 임포터(편집용 불러오기)에는
  적용하지 않음 — 원본 값을 그대로 보존.

**추가된 파일**
- `src/lib/designerXml.js` — `looksLikeDesignerXml()`(루트 태그로 빠르게 판별),
  `convertDesignerXmlToScenarioXml()`(위 규칙을 그대로 구현).

**수정된 파일**
- `src/App.jsx` — meta import를 `sample-meta.json` → `designer.meta.json`으로 교체.
  `handleFileSelected`/`loadPageIntoCanvas`에서 읽은 텍스트를
  `resolveScenarioXml()`(디자이너 포맷이면 변환, 아니면 그대로 통과)에 거쳐서
  `initialXml`에 반영. 변환 중 meta에 없는 노드 타입이 있으면 알림.
- `src/components/PropertyPanel.jsx` — **진짜 버그 수정**: 모든 프로퍼티를 항상
  `userData.attr(buildName)`로만 읽고 썼는데, `CData`/`XmlChild` 프로퍼티는 애초에
  속성이 아니라서 늘 `null`만 반환하고 쓰기도 조용히 무시되고 있었음(스크립트 계열
  프로퍼티가 항상 빈 에디터로 보이는 원인). `readPropertyValue`/`writePropertyValue`
  헬퍼로 `buildDataType`에 따라 분기하도록 수정.
- `scripts/gen-util-dts.cjs` — `designer.meta.json`에 이미 구조화된 `utilFunctions`
  (label/insertText/documentation)가 있어서, 기존의 `ScriptNode.description` 텍스트
  정규식 파싱 방식을 걷어내고 그 배열을 그대로 `.d.ts`로 변환하도록 단순화.
  `src/lib/scriptUtilTypes.generated.js`도 재생성(51개 함수).
- `src/components/DiagramCanvas.jsx` / `src/lib/blockGrouping.js` — `sample-meta.json`
  언급 주석을 `designer.meta.json`으로 갱신 (로직 변경 없음).

**검증 (실제 `123.prj` + `123.xml`, 1.5MB, 합성 데이터 아님)**
- 140개 블록 전부 로드, 타입별 개수까지 정확히 일치 (ScriptNode 34, GotoPageNode 35,
  SwitchNode 5 등 16종).
- `IfNode`의 `condition` 값과 true/false 링크 정상 연결.
- `ScriptNode`의 실제 스크립트(1906자)가 에디터에 화면으로도 정확히 표시됨 (CData
  버그 수정의 실제 회귀 테스트).
- `SwitchNode`의 동적 분기 7개 전부 정상 연결 — "동적 분기도 특수 처리 불필요"
  가설 확정.
- `designer.meta.json`이 실제 파일의 노드 타입을 전부 커버(스킵된 타입 없음),
  콘솔 에러 없음.

**특이점**
- `diagram-library.js`는 이번에도 전혀 건드리지 않음 — 변환은 전부 `designerXml.js`
  안에서 끝내고, 결과물만 기존 `Diagram.deserialize()`에 그대로 넘김.
- `CData` 데이터를 진짜 `<![CDATA[...]]>` 섹션으로 쓸 필요는 없었음 — 일반 텍스트
  노드로 저장해도 직렬화 시 특수문자가 엔티티 이스케이프되어 왕복이 정확히 보존됨
  (`NodeWrapper.toString()`이 처리).
- 범위 밖으로 명시: `MemoNode` 변환(블록/링크만 다룸), `GotoPageNode`/`CallPageNode`가
  다른 페이지를 가리킬 때 자동 이동, `RawXML` 타입 프로퍼티 전용 편집 UI.

## 4. 리본 "삽입" 탭 — 카테고리 플라이아웃으로 재설계

`designer.meta.json` 전환으로 노드가 13종 → 66종으로 늘면서, 삽입 탭을 열면 화면
절반 가까이 차지하는 문제가 생김. 카테고리 버튼 한 줄 + 클릭 시 플라이아웃 드롭다운
방식으로 재설계 (여러 안 중 사용자가 "카테고리 드롭다운" 선택).

- 리본은 이제 다른 탭들과 같은 높이 — 색상별 카테고리 버튼 4개(시나리오/컨트롤/
  음성/서비스, 항목 수 배지 포함)만 한 줄에 보임.
- 카테고리 클릭 시 그 아래 플라이아웃: 검색창(타이핑으로 즉시 필터링) + 노드 그리드.
  바깥 클릭이나 노드 선택 시 자동으로 닫힘.
- **그리드 칸 크기 문제**: 처음엔 고정 68px 칸에 라벨을 2줄+말줄임(`...`)으로
  넣었는데, "CTI 호전환"/"CTI 호전환 완료"/"CTI 호전환 재접속"처럼 접두어가 같은
  라벨들이 전부 "CTI 호전환..."로 뭉개져 구분이 안 된다는 피드백. 말줄임을 없애고,
  캔버스 2D 컨텍스트로 그 카테고리에서 가장 긴 라벨의 실제 렌더링 폭을 측정해서
  모든 칸을 그 폭에 맞추도록 변경 — 라벨이 전부 한 줄로 잘리지 않고 보임. 플라이아웃
  전체 폭도 칸 폭×열 개수(최대 4열)로 같이 계산해서, 짧은 라벨 카테고리는 여전히
  촘촘하게, 긴 라벨이 있는 카테고리는 자동으로 넓어짐.

**수정된 파일**
- `src/components/RibbonMenu.jsx` — 기존 `groupNodesByCategory` 순회 렌더링을
  `InsertCategoryRow`/`InsertCategoryFlyout`로 교체. `measureWidestLabelWidth()`가
  칸 폭을, 그 결과로 플라이아웃 폭을 계산.
- `public/css/ribbon-menu.css` — `.ribbon-insert-*` 클래스 전부 신규. 칸 폭은
  `--ribbon-insert-col-width` CSS 변수로 JS가 인라인 주입.

**특이점**
- 칸 폭 측정은 `.ribbon-button-label`과 동일한 폰트 문자열로 오프스크린
  `<canvas>` 하나를 재사용해서 측정 — DOM에 붙이지 않고, 카테고리 전환/검색마다
  다시 만들지 않음.
- 검색으로 필터링되어도 칸 폭은 카테고리 전체 기준으로 고정 — 타이핑할 때마다
  칸 크기가 들썩이는 걸 방지.
